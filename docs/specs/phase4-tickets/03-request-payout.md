## ที่ตัดสินใจระหว่างทาง

**ยอดถอนได้ = `min(ยอดค้างจ่ายจริง, รายได้ที่สุกแล้ว − ที่ขอไปแล้ว)`**
สองเงื่อนไขคนละเรื่องและต้องผ่านทั้งคู่ — อันแรกกันถอนเกินที่มีจริง อันหลังกันถอนเงิน
ที่ยังไม่พ้นระยะรอ · ใช้อันใดอันหนึ่งอย่างเดียวไม่พอ

**`internal_payout_quote` เป็นฟังก์ชันเดียวที่ทั้ง preview และการบันทึกจริงเรียก**
ถ้าคิดเลขกันคนละที่ วันหนึ่งจะเพี้ยนแล้วผู้ใช้เห็นเลขหนึ่งแต่ถูกบันทึกอีกเลขหนึ่ง
· เทสตรวจตรง ๆ ว่า preview กับที่บันทึกได้ตัวเลขเดียวกัน

**ตัวกันถอนซ้อนอยู่ที่ unique partial index ไม่ใช่ที่โค้ด** — โค้ดที่เช็คก่อน insert
แพ้ race ได้เสมอ · ดัก `unique_violation` แล้วแปลงเป็น `payout_already_pending`

## บั๊กที่เจอระหว่างทาง

**definer view เรียกฟังก์ชันที่ revoke ไว้ไม่ได้** — `v_my_payout_summary` พังด้วย
`permission denied for function get_config` เพราะ definer view ใช้สิทธิ์เจ้าของกับ**ตาราง**
แต่การเรียก**ฟังก์ชัน**ยังเช็คสิทธิ์ของผู้เรียก → อ่าน `app_config` ตรง ๆ ใน view แทน

**เทส "ขอซ้อน" ผ่านด้วยเหตุผลผิดตั้งแต่รอบแรก** — ขอถอนทั้งหมดไปแล้ว รอบสองเลยแดง
เพราะเงินหมด ไม่ใช่เพราะตัวกันถอนซ้อน **ตัว unique index ไม่เคยถูกทดสอบเลย**
→ แก้เป็นขอแค่ขั้นต่ำ เหลือเงินไว้ 1000 เหรียญ แล้วบังคับว่าต้องแดงด้วย
`payout_already_pending` เท่านั้น
