## ที่ตัดสินใจ

**การจ่ายจริงไม่แตะ ledger เลย** — เหรียญออกไปตั้งแต่ตอน `requested` แล้ว
สิ่งที่แตะเงินคือทางที่ "ไม่ได้จ่าย" เท่านั้น (reject / cancel) ซึ่งคืนด้วย **reversing entry**
ที่ชี้ `reversal_of` กลับต้นฉบับ ไม่ใช่โพสต์ขาบวกใหม่ · ตัวกันกลับซ้ำคือ unique index
บน `reversal_of` ที่มีอยู่แล้ว ไม่ใช่โค้ด

**รวม approve/reject/mark_paid ไว้ใน RPC เดียว** เพราะทั้งสามเลื่อนสถานะของคำขอเดียวกัน
และต้องล็อกแถวเดียวกัน แยกเป็นสาม RPC จะเปิดช่องให้เรียกสลับลำดับได้

**`mark_paid` บังคับเลขอ้างอิง** — เป็นหลักฐานเดียวที่โยงรายการนี้กับ statement ธนาคาร

## เรื่องใหญ่ที่เจอตอนตรวจ: เทสข้ามตัวเองเงียบ ๆ

`testSeerCanCancel...` ใช้ `XCTSkipUnless` แล้ว**ข้ามตัวเองทุกรอบที่สอง** โดยที่
`test-ios.sh` ยังขึ้น `TEST SUCCEEDED` — failure mode เดียวกับที่เคยเจอตอนชุด REST
ชี้ cloud แล้วข้ามทั้งชุดเงียบ ๆ

แก้สามชั้น:
1. **`test-ios.sh` ดักตัวที่ข้ามแล้ว fail** (ปลดล็อกด้วย `ALLOW_SKIPPED=1`)
2. **เอา `XCTSkipUnless` ออก** เปลี่ยนเป็นพิสูจน์ขาตรงข้ามแทน — เงื่อนไขไม่พร้อมก็ต้อง
   พิสูจน์ว่า "ขอถอนไม่สำเร็จและเหรียญไม่ขยับ" ไม่ใช่ไม่ทำอะไรเลย
3. **fixture กำหนดสถานะตั้งต้นให้ครบ** — บัญชีรับเงินที่ตรวจแล้ว + รายได้ที่พ้นระยะรอ 2000 เหรียญ
   + เคลียร์คำขอถอนที่ค้างจากรอบก่อน · ไม่งั้นขาที่ควรทดสอบจริงจะไม่เคยถูกเดินเลย

**ยืนยันว่าแก้ได้จริงด้วยการนับแถวในฐาน** ไม่ใช่เชื่อว่าเทสเขียว:
คำขอที่ถูกยกเลิกเพิ่มขึ้น 1 รายการทุกครั้งที่รันชุด iOS

## เรื่องเครื่อง

`test-ios.sh` ปิด parallel testing แล้ว (`-parallel-testing-enabled NO`) —
ค่าเริ่มต้นของ xcodebuild โคลน simulator ขึ้นมาหลายตัวพร้อมกัน ซึ่งกินแรมหนักมาก
ชุดนี้ยิงฐานเดียวกันอยู่แล้ว รันขนานไม่ได้ช่วยอะไร · เปิดกลับด้วย `PARALLEL_TESTS=1`
