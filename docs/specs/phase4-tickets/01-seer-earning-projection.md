# 01: หมอดูเห็นรายการรายได้ของตัวเอง

**What to build:** หมอดูเปิดแอปแล้วเห็นว่ารายได้แต่ละก้อนมาจากงานไหน ลูกค้าจ่ายมาเท่าไหร่
หักส่วนแบ่งแพลตฟอร์มแล้วเหลือเท่าไหร่ และเกิดขึ้นเมื่อไหร่ — ตรวจได้ว่าแพลตฟอร์มคิดถูก

ก้อนนี้เป็นฐานของทั้งเฟส เพราะ **ระยะรอก่อนถอนได้คิดจากวันที่ของรายได้แต่ละก้อน**
ถ้าไม่มี projection นี้ก็ไม่มีทางรู้ว่าเหรียญก้อนไหนสุกแล้ว · ตอนนี้ตอนปิดงานระบบโพสต์ ledger
อย่างเดียว ไม่ได้บันทึกว่ารายได้ก้อนนั้นมาจากงานอะไร (คอมเมนต์ใน migration เขียนไว้เองว่ายกไปทีหลัง)

**Blocked by:** None (can start immediately)

**Status:** done (2026-08-29)

- [x] ปิดงานหนึ่งครั้ง → เกิดรายการรายได้หนึ่งรายการ ในทรานแซกชันเดียวกับ ledger ไม่ใช่คนละจังหวะ
- [x] รายการเก็บอัตราส่วนแบ่ง ณ ตอนนั้นไว้ด้วย — เปลี่ยนอัตราทีหลังแล้วรายการเก่าต้องไม่เปลี่ยนตาม
- [x] งานเดียวสร้างรายได้ได้ครั้งเดียว ต่อให้ยิง settle ซ้ำ
- [x] รายได้ที่ปิดงานไปแล้วก่อนมี ticket นี้ ถูกเติมย้อนหลังจาก ledger จนยอดรวมตรงกับ `payable_coin` ปัจจุบัน
- [x] แต่ละรายการโยงกลับไปหาหลักฐานทางบัญชีใน ledger ได้
- [x] หมอดูอ่านของตัวเองได้ อ่านของคนอื่นไม่ได้ (พิสูจน์ด้วยบัญชีที่สอง)
- [x] หมอดูเขียนทับรายการเองไม่ได้
- [x] แอปแสดงรายการรายได้ให้หมอดูเห็นจริงบนหน้าจอ ไม่ใช่แค่มีข้อมูลในฐาน

### เทสสองข้อที่เกือบเขียวด้วยเหตุผลผิด

ตอนรอบแดง มีสองข้อที่ผ่านทั้งที่ตารางยังไม่มี:
- "หมอดูเขียนรายได้เองไม่ได้" ผ่านเพราะรับ error อะไรก็ได้ → เจอ `PGRST205` (ไม่มีตาราง) ก็เขียว
  **แก้เป็นบังคับ `42501` เท่านั้น**
- "คนอื่นอ่านไม่เห็น" นับ `length` ของ error object ได้ 4 → **แก้เป็นบังคับว่าต้องเป็นอาเรย์ว่าง**

### บั๊กที่ทำพังเองแล้วเกือบหลุด

ตอนแก้ `internal_settle_question` ก็อปตัวฟังก์ชันมาจาก migration `20260827000001`
ซึ่งเป็น**ตัวเก่า** ไม่ใช่ `20260827000003` ที่แก้บั๊ก "ส่วนแบ่งปัดลงเป็นศูนย์" ไว้แล้ว
→ **revert การแก้บั๊กของคนอื่นโดยไม่รู้ตัว** ทำให้คำถามราคาต่ำปิดไม่ได้ตลอดกาล
และเหรียญค้างใน escrow

ที่เจอเพราะเพิ่ง**ทำ `scripts/test-sql.sh` ขึ้นมา** — การตรวจด้วยมือรอบก่อนหน้าใช้ pattern
`^(ERROR|WARNING)` ซึ่งไม่แมตช์ `psql:<stdin>:173: ERROR:` เลย จึงรายงานว่าผ่านทั้งที่ล้มจริง

**บทเรียน: `create or replace function` ในไฟล์ migration ใหม่ = เขียนทับของล่าสุดทั้งตัว
ต้องหาให้เจอก่อนว่าตัวล่าสุดอยู่ไฟล์ไหน ไม่ใช่ไฟล์ที่นิยามมันครั้งแรก**
