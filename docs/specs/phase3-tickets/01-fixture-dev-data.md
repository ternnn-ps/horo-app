# 01: Fixture — สร้างสถานะตั้งต้นด้วยคำสั่งเดียว

**What to build:** นักพัฒนารัน `supabase db reset` แล้วรัน script เดียว จบ — ได้ฐานข้อมูลที่พร้อมทดสอบทันที
มีบัญชีผู้ใช้ทดสอบ, บัญชีหมอดูที่**ผ่านการอนุมัติแล้ว**พร้อม skill และ service ที่มีราคา, และเหรียญตั้งต้นในกระเป๋าผู้ใช้
script ต้องบอกผลลัพธ์ที่จำเป็นต่อการทดสอบออกมาให้อ่านได้ (อีเมล/รหัสผ่านที่ใช้ login, account id, service id, ยอดเหรียญ)

เหตุผลที่ต้องมี: `auth.users` seed ผ่าน migration ไม่ได้ ต้องสร้างผ่าน API/CLI — ถ้าไม่มี script นี้
ทุกครั้งที่ reset ต้องสมัครบัญชีและอนุมัติหมอดูด้วยมือใหม่หมด ซึ่งจะทำให้ทีมเลี่ยงการ reset แล้วไปเทสบนฐานสกปรก

**Blocked by:** None (can start immediately)

**Status:** ready-for-agent

- [ ] รันซ้ำได้โดยไม่พัง (idempotent) — รันสองรอบติดกันไม่เกิด error และไม่เกิดข้อมูลซ้ำ
- [ ] หมอดูที่สร้างมีสถานะพร้อมรับงานจริง: อนุมัติแล้ว, `is_active`, `accepts_question`, มี service ที่เปิดใช้งาน
- [ ] ผู้ใช้ทดสอบมีเหรียญพอซื้อ service ของหมอดูตัวนั้นได้อย่างน้อย 3 ครั้ง
- [ ] `submit_question` จากบัญชีผู้ใช้ทดสอบไปยัง service ของหมอดูทดสอบ สำเร็จ (พิสูจน์ว่า fixture ใช้งานได้จริง ไม่ใช่แค่มีแถวในตาราง)
- [ ] script ทำงานกับทั้ง local และ cloud ได้ โดยชี้เป้าด้วยค่าตัวแปร ไม่ต้องแก้โค้ด
- [ ] มีคำเตือนกันรันบน production
