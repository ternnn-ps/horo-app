# 04: ซื้อคำถาม — เหรียญเข้า escrow

**What to build:** ผู้ใช้เลือกบริการของหมอดู พิมพ์คำถามแรก กดส่ง แล้วเหรียญถูกกันไว้ (escrow) จริง
เห็นยืนยันว่าถูกกันไปเท่าไหร่และคำถามหมดอายุเมื่อไหร่ · ถ้าเหรียญไม่พอ ต้องรู้ **ก่อน** พิมพ์คำถามยาว ๆ
· ถ้าส่งไม่สำเร็จแล้วกดใหม่ หรือเน็ตหลุดแล้วแอปยิงซ้ำ **ต้องไม่หักเหรียญสองรอบ**

หัวใจของ ticket นี้คือ idempotency: `client_request_id` และ `client_message_id` ต้องถูกสร้าง
**ตอนผู้ใช้เริ่มร่างคำถาม** ไม่ใช่ตอนกดส่ง เก็บไว้กับ draft นั้น และ retry ทุกครั้งส่งค่าเดิม
จนกว่าจะสำเร็จหรือผู้ใช้ทิ้ง draft — RPC คืน `replayed: true` เมื่อเจอ key ซ้ำและไม่หักเหรียญอีก

ก้อนนี้เป็นก้อนแรกที่เจอ error จาก RPC จึงเป็นที่ตั้งของตัวแปลง error → ข้อความไทย ซึ่งต้องอยู่จุดเดียว

**Blocked by:** 03 (Seer discovery)

**Status:** ready-for-agent

- [ ] ยอดเหรียญบนหน้าจออ่านใหม่จาก server หลังซื้อเสร็จ — ไม่ลบยอดในเครื่องเอง
- [ ] **ยิงซ้ำด้วย key เดิม → `replayed: true` และยอดเหรียญไม่ขยับรอบสอง** (มี test พิสูจน์)
- [ ] เหรียญไม่พอ → บอกก่อนกดส่ง และถ้าหลุดไปถึง server จริงต้องได้ `insufficient_coin` โดย**ไม่มีแถว question เกิดขึ้น**
- [ ] error code ทุกตัวที่ RPC โยนได้ มีข้อความไทยที่จุดเดียว และ code ที่ไม่รู้จักมีข้อความสำรอง
