# 12: เอาข้อมูลโดเมนออกจาก UserDefaults

**What to build:** สองหน้าจอที่ยังเก็บข้อมูลโดเมนไว้ในเครื่อง ต้องเลิกโกหกผู้ใช้ —
ให้ข้อมูลมาจากเซิร์ฟเวอร์ หรือไม่ก็เอาฟีเจอร์ออกไปเลย ไม่ใช่ปล่อยให้แก้แล้วไม่ถึงไหน

**Blocked by:** 09 (Remove legacy domain)

**Status:** ready-for-agent

## ที่มา

แยกออกมาจาก ticket 09 ตอนสำรวจของจริง (2026-08-29) — เกณฑ์ข้อ "ไม่มีการอ้าง `UserDefaults`
สำหรับข้อมูลโดเมนเหลืออยู่" ของ 09 ทำไม่ได้ในก้อนนั้น เพราะของที่เหลือ**ไม่ใช่ domain เก่าที่ตายแล้ว**
แต่เป็นฟีเจอร์ที่ยังมีหน้าจอใช้อยู่จริง ลบทิ้งเฉย ๆ คือลบฟีเจอร์ และจะย้ายขึ้นเซิร์ฟเวอร์ก็ยังไม่มีตารางรองรับ

## สองที่ที่เหลือ

**1. โปรไฟล์ผู้ใช้ — `UserProfileViewModel` + `UserDefaultsUserProfileStore`** (key `horo-test.user-profile`)

อันตรายกว่าอีกอัน: ชื่อจริงของผู้ใช้อยู่ที่ `account` / `seer_profile` บนเซิร์ฟเวอร์อยู่แล้ว
แต่หน้าจอให้แก้ชื่อ/อีเมลแล้วเก็บลงเครื่อง **แก้ไปก็ไม่มีใครเห็น** อีกฝั่งยังเห็นชื่อเดิม
เป็นบั๊กพันธุ์เดียวกับที่เจอตอนปิดงานแล้วยอดไม่ขยับ: หน้าจอเล่าเรื่องที่ไม่ตรงกับความจริงของระบบ

**2. บันทึกงานของหมอดู — `RecordListViewModel` + `RecordStoring` + `TestRecord`** (key `horo-test.records`)

ขับ Dashboard ฝั่งหมอดู (สร้าง/แก้/ติ๊กเสร็จ/ลบ) ยังไม่มีตารางบนเซิร์ฟเวอร์รองรับ
ต้องตอบก่อนว่านี่เป็นฟีเจอร์จริงของ Chata หรือเป็นของเหลือจาก template ตอนตั้งโปรเจกต์

- [ ] ตอบให้ได้ก่อนลงมือ: บันทึกงานหมอดูเป็นฟีเจอร์จริงไหม — ถ้าไม่ใช่ ลบหน้าจอทิ้งให้จบ
- [ ] แก้โปรไฟล์แล้วต้องถึงเซิร์ฟเวอร์จริง และอีกฝั่งเห็นชื่อใหม่ (หรือถ้ายังไม่ทำ ต้องปิดปุ่มแก้ไข ไม่ใช่ปล่อยให้กดได้แล้วเงียบ)
- [ ] ไม่มีการอ้าง `UserDefaults` สำหรับข้อมูลโดเมนเหลืออยู่ (session ของ SDK ไม่นับ)
- [ ] ถ้าเลือกทางย้ายขึ้นเซิร์ฟเวอร์: มี migration + RLS + เทสที่พิสูจน์ว่าคนอื่นอ่าน/แก้ของเราไม่ได้
- [ ] เทสเดิมที่ผูกกับ store ในเครื่อง (`RecordListViewModelTests`, `UserProfileViewModelTests`) ถูกแทนหรือถูกลบพร้อมฟีเจอร์
