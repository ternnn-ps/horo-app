# 05: แชท + Realtime

**What to build:** ผู้ใช้เปิดคำถามที่ซื้อไว้ เห็นประวัติข้อความ พิมพ์ส่งเพิ่มได้ และ**ข้อความจากอีกฝ่ายโผล่เอง
โดยไม่ต้องกดรีเฟรช** · เห็นสถานะของข้อความตัวเอง (กำลังส่ง / ส่งแล้ว / ล้มเหลว) และกดส่งซ้ำได้
โดยไม่เกิดข้อความซ้ำสองอัน · คำถามที่ปิดไปแล้วต้องพิมพ์ต่อไม่ได้ · เหตุการณ์ระบบ (ขอปิดงาน/ปิดแล้ว/คืนเงิน)
แสดงในสายแชทเดียวกัน

ก้อนนี้รวม migration เปิด `supabase_realtime` publication ให้ `question_message` และ `question`
(ยังไม่มี migration ไหนเปิดให้ตารางใดเลย) · Realtime เคารพ RLS เดิมอยู่แล้ว ไม่ต้องเขียน policy เพิ่ม
· Realtime ส่งเฉพาะของใหม่ ตอนเข้าห้องยังต้อง fetch ประวัติตามปกติ

**Blocked by:** 04 (Buy question)

**Status:** ready-for-agent

- [ ] ส่งข้อความผ่าน insert ตรงตาม RLS (ไม่ใช่ RPC — ไม่แตะเงิน) และเห็นในห้องทันที
- [ ] อีกฝั่งส่งมา → ข้อความโผล่เองภายในไม่กี่วินาที โดยไม่ต้องรีเฟรช
- [ ] ส่งซ้ำด้วย `client_message_id` เดิม → ไม่เกิดข้อความซ้ำ (unique `(question_id, client_message_id)`)
- [ ] ข้อความเรียงถูกต้องด้วย `id` ที่เป็น Int64 ไม่ใช่ UUID
- [ ] คำถามสถานะปิด → composer ปิดตัวเอง พร้อมบอกเหตุผล
- [ ] ข้อความชนิด `system` แสดงต่างจากข้อความคน
- [ ] integration test: ผู้ใช้ที่ไม่ใช่คู่สนทนา **อ่านข้อความห้องนั้นไม่เห็น** และ insert เข้าห้องนั้นไม่ได้
